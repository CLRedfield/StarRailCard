# 星穹骰局 · StarRailCard

**[在线游玩](https://clredfield.github.io/StarRailCard/)** · [部署状态](https://github.com/CLRedfield/StarRailCard/actions/workflows/deploy.yml)

参考《崩坏：星穹铁道》「上骰了！战力党！」与「又上骰了！战力党！」制作的非盈利同人网页小游戏。支持经典 1v1、双人共斗、4～8 人多人派对、本地养成、全卡池自由对战，以及通过公共服务器与好友联机。

项目使用 React、TypeScript、Vite、Three.js 与 MQTT。游戏规则在浏览器运行，静态文件即可部署，无需自建游戏服务器。

## 运行

使用 Node.js 22 或 24 与 npm。在项目目录执行：

```sh
npm install
npm run dev
```

开发服务默认使用 **5177** 端口，打开 [本地游戏](http://localhost:5177)。如果端口被占用，以 Vite 终端打印的地址为准。

```sh
npm run build
npm run preview -- --port 5177
npm test
```

`build` 先执行 TypeScript 检查，再生成 `dist/`；`preview` 用于预览构建结果；`test` 运行 Vitest。默认测试不连接公共服务器，真实联机测试的单独运行方式见 [联机文档](docs/networking.md)。

已附带规范化游戏数据和原始 PNG，正常启动不需要重新下载。重新生成数据与校验资产时使用 Python 3：

```sh
npm run data:sync
python scripts/verify_data.py
```

同步脚本会访问固定历史提交，原始大表与文本缓存放在 `.cache/release-data/`。Python 用于完整保留超过 JavaScript 安全整数范围的文本 Hash。

## 内容与模式

收录 37 张可收集角色卡（36 张原版＋同人希儿）、28 张教程/NPC/Boss 专用卡、25 种可装备真曜彩骰及其基础变体、24 张战术卡、31 条天气规则、28 条术语，以及 272 张原作 PNG 贴图。NPC 与 Boss 卡不混入玩家合法收藏。

新增希儿：28 生命、攻击 3、防御 3，命中后以剩骰点数造成一次再现瞬伤，未造成攻击伤害则升级所选普通骰。自由卡池直接可用，养成商店售价 6 战力币。刃调整为额外 +2 次重投（通常攻 4／防 2）；绯英单骰调整为忽略 7 点防御。详细规则见 [同人角色与平衡调整](docs/custom-characters.md)。

挑战页分为四类：

| 入口 | 内容 | 进度方式 |
| --- | --- | --- |
| 上骰了 | 11 场经典战役 | 按顺序挑战，保留原始对手与天气序列 |
| 又上骰了 | 6 场故事共斗与 5 场进阶强敌 | 与 AI 队友合作，挑战多阶段首领 |
| 赠卡挑战 | 斯科特、砂金、姬子 3 场特别对局 | 达到相应故事里程碑后获得角色卡 |
| 街头切磋 | 116 场原始普通牌手配置 | 经典第一战后开放，可按角色名、难度和完成状态筛选 |

养成模式从火花花与 **6 战力币新手补给**开始，可先在商店购入基础角色；旧存档更新后在原余额上补发一次，刷新或导入已领取的新档不会重复领取。这是网页版的入门补给，原始商品价格、解锁条件、挑战首胜和资历奖励保持不变。商店提供角色、曜彩骰和镀闪；资历最高 25 级，镀闪只改变外观，不提高数值。见 [补给与迁移说明](docs/starter-funds.md)。

经典第一关自带可交互教学：认清攻防、选骰与滑选、实际重投、按数量确认、阅读真实伤害、完成防守。教学跟随本局操作推进，读取结算时对手等待；可随时跳过或重看，刷新后随对局恢复。无需花钱即可使用初始角色学习，第一关仍保留原始对手和首胜奖励。

首页「开始对战」、共斗入口及联机开放完整卡池。自由配置与养成配置分别保存，自由和联机对局不会给养成账户发放故事资源。商城、赠卡、资历奖励与街头挑战共同提供全部可收藏角色、真曜彩骰及镀闪所需资源。

## 上桌操作

1. 在挑战入口或自由对战中选择角色与曜彩骰，进入牌桌。
2. 点击骰子使其处于选中状态，也可以在牌桌空白处按住鼠标或手指，再划入骰排批量选择，不必从骰子上起手；从已选中的骰子开始划动则批量取消。再决定重投还是用于本回合攻防。
3. 点击「重投」重新投掷选中的骰子，其他骰子留在原位、保持原点数。重投结束后重新选择。进攻通常可重投两次，防御通常没有重投，角色技能和天气可能改变次数。
4. 点击曜彩骰按钮投出特殊骰子，再选择是否使用它；通常每局可用两次。已经投出的曜彩骰也能重投，特殊面须被选中参与结算才生效。
5. 选好本回合要使用的骰子后点击「确认使用」。确认时的数量必须满足攻击或防御等级，特殊技能另有规则；该数量要求不用于限制一次重投的骰子颗数。攻击值、防御值和技能共同决定结算结果。

共斗时，双方选骰后会进入交换阶段。先点击自己的已选骰，再点击共享区目标骰完成交换，也可拖放。战术卡在交换阶段使用；战术商店可购买、刷新，准备完成后继续。队伍共享三次生命，需要击破首领的全部阶段。

点击角色头像查看技能和状态；点击天气图标查看当前规则；牌桌右上角可查看操作说明与对局记录。收藏中的规则手册提供角色、骰子、天气、战术和术语图鉴。

对战准备和联机准备会随选择显示角色完整技能、初始骰池、曜彩骰次数及默认配置。曜彩骰按六个骰面分别显示点数、特殊效果与使用条件；相同点数的不同效果以面序号区分。收藏中的曜彩骰也能直接查看各面，并点开完整说明和效果释义，未收集的骰子仍可查阅。

确认后，先播放跃升、骇入的具体骰面变化，再在红蓝牌桌上同时展示双方最终攻防值，随后播放角色卡攻击、护盾与伤害。生命归零后，播放金色像素 KO、粉红立方碎片和金白放射光，再进入胜负结算；共斗复起与首领换阶段也会先完成击破演出。最终数值取自本轮真实结算，包含技能改骰、战术和支援修正。减少动态效果会保留简短的静态数值对照与 KO。

默认使用亮色主题，旧存档未设置主题时也使用亮色。只在活动首页右上角提供亮色／暗色切换，选择会随存档保存。

手机主要使用竖屏游玩，首页与准备界面纵向排布，对战操作集中在底部；同时保留电脑与手机横屏支持。设置中可切换全屏、调整音乐与音效、减少动态效果或降低渲染质量。音频会在首次交互后启用。

拟替换音乐与关键音效的原创制作提示词已整理为 [Suno 生成指南](docs/suno-audio-prompts.md) 和 `release/Suno生成提示词.txt`，含 3 条 BGM、胜败提示与掷骰、攻击、毒伤等声音描述。现有程序合成音频尚未替换；参考试听链接不等于已取得或已接入音频文件。

## 好友联机

新增「多人派对」入口：**银河夺宝、裂界远征、双人搭档乱斗、首领降临**。支持 4～8 人（搭档模式为 4／6／8 人）、AI 补位、同时计划、队友换骰、局间强化，以及本地练习和多人好友房。角色与骰子共用原规则引擎，模式规则单独维护；玩法、调角色与新增角色的边界见 [多人派对说明](docs/party-modes.md)。

默认使用与 `hearthStoneKill2` 相同的公共服务器：`wss://broker.emqx.io:8084/mqtt`。本项目使用独立主题 `starrailcard/v2`，与原游戏房间隔离。

1. 打开「联机」，选择 1v1 或双人共斗，创建房间。
2. 分享六位房间号或邀请链接。仅使用房间号时，双方应选择同一服务器。
3. 双方选择角色、曜彩骰和外观，点击「准备就绪」，由房主开始。

也可使用快速匹配。当前联机协议为 v2，双方更新后需要重新建房，旧联机检查点不能续接，养成进度保留。选骰与攻防预览立即在本地完成，确认、重投、换骰和战术等节点由房主统一结算；对局中断后会暂停并尝试恢复，刷新后可从联机大厅恢复保存的房间。更换线路需要重新建房，已有对局不会跨服务器迁移。

公共 MQTT 服务传输房间和对局信息，不提供私密房间、身份认证或反作弊保障；房间号不是访问密钥。连接可用性取决于公共服务与双方网络。协议、恢复流程及边界见 [联机说明](docs/networking.md)。

## 存档

养成、自选配置、未结束本地对局与联机检查点自动写入浏览器 IndexedDB；不可用时尝试 localStorage。设置中的「导出存档」「导入存档」用于迁移**养成档案**，不导出整个对局或联机房间。

存档属于当前浏览器与网站来源；更换端口、域名或浏览器会使用不同存储。清理网站数据前可先导出养成档案。

## 静态部署

### GitHub Pages

在线地址：**https://clredfield.github.io/StarRailCard/**。

仓库使用 `.github/workflows/deploy.yml` 自动部署：每次推送到 `main`，GitHub Actions 使用 Node.js 24 执行 `npm ci`、`npm test` 和 `npm run build`，检查通过后将 `dist/` 发布到 GitHub Pages。也可在 Actions 的「Deploy to GitHub Pages」页面手动运行。构建会读取 Pages 的部署路径设置 `BASE_URL`，确保图片、音频和脚本在 `/StarRailCard/` 下正常加载。

首次部署或 fork 到其他仓库时，在仓库 **Settings → Pages → Build and deployment → Source** 中选择 **GitHub Actions**。之后的更新只需提交源码并推送，不需要提交 `dist/` 或手工上传网页文件。配置参考 [GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) 与 [Vite 部署说明](https://vite.dev/guide/static-deploy)。

`.gitignore` 排除依赖、缓存、构建结果、测试报告、本地环境配置及生成的发布 ZIP／打包报告；`package-lock.json`、游戏数据和 `public/` 中的图片、音频仍随源码保存，以便完整重建网站。

### 其他静态托管与 Toy

Bilibili Toy 发布文件与素材位于 `release/`，上传方式见 [Toy 发布说明](docs/toy-release.md)。执行 `npm run build` 后，运行 `python scripts/package_toy.py` 可重新生成入口位于根目录的部署 ZIP。打包时通过 SHA-256 合并完全相同的图片副本，保留原画质和全部内容；当前 ZIP 约 38.90 MB，并对 ZIP 与解压大小都执行 50,000,000 字节上限检查。

构建后将整个 `dist/` 上传到静态站点。默认 `BASE_URL` 为 `./`，资源使用相对路径；也可在构建时指定部署子目录。以 PowerShell 为例：

```powershell
$env:BASE_URL='/StarRailCard/'
npm run build
Remove-Item Env:BASE_URL
```

POSIX shell 对应命令：

```sh
BASE_URL=/StarRailCard/ npm run build
```

上例对应网站的 `/StarRailCard/` 路径，保留末尾斜杠。部署根目录可设为 `/`。应通过 HTTP(S) 服务访问构建产物，不直接双击 `dist/index.html`。游戏使用页内导航，不要求服务器配置多页面路由。

原始 PNG 合计约 66 MB，请完整发布 `dist/assets/`；人物图片按界面需要加载。对外分享邀请时使用部署后的站点地址，本机 `localhost` 地址不能作为好友的访问地址。

## 复现范围与素材来源

数据基于 4.0、4.2 的已发布版本历史提交，来源为 [Dimbreath / TurnBasedGameData](https://gitlab.com/Dimbreath/turnbasedgamedata)；原始贴图来源为 [umaichanuwu / StarRailTextures](https://github.com/umaichanuwu/StarRailTextures)。每张素材与每个原表的固定来源、提交和 SHA-256 记录随源码保存。

上游表引用的原始技能运行脚本未公开收录。本项目按数值、文本、教程及公开玩法资料手写规则引擎；复杂技能叠加、效果触发顺序和特殊边界仍需要与原作录像逐项核对，不能视为已证明逐帧、逐规则完全一致的原客户端移植。部分重复键常量的映射与曜彩骰槽位含义保留了明确的推断记录。

网页不复现完整大世界行走、3D 剧情演出及对白任务。赠卡入口、街头牌局入口和部分任务解锁被改编为便于直接游玩的挑战；原作角色、美术和文本予以保留。界面布局、立体骰子、卡牌光效、伤害与转场动效为网页实现；背景音乐和交互音效由 Web Audio 程序合成，未使用原作完整音轨。

本项目与 HoYoverse 无隶属关系。原作角色、美术、文本和名称归相应权利人所有；此处用于非盈利同人展示与游玩，不连接原游戏账号或奖励系统。

- [素材与数据来源](docs/sources.md)：版本提交、归档来源与重建方式。
- [数据说明](docs/data-notes.md)：准确覆盖范围、养成映射、原始字段与已知边界。
- [选骰与重投核验](docs/dice-interaction-review.md)：原教程配置、文本 Hash、实机时间点及证据边界。
- [阵亡演出核验](docs/death-animation-review.md)：原作 KO 连续画面、重建特征与未复刻边界。

## 代码位置

- `src/game/`：规则状态、技能、AI 与确定性结算。
- `src/data/`：规范化卡牌、骰子、关卡、奖励及来源清单。
- `src/components/`：卡牌、牌桌、挑战、收藏、商城与联机界面。
- `src/net/`：MQTT 传输、房间与对局状态同步。
- `src/lib/`：本地存档、养成与合成音频。
- `scripts/`：固定版本数据导入、素材获取与完整性校验。
- `public/assets/`：原始 PNG；`tests/`：规则、养成与联机测试。
