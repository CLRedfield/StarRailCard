# 可复现的银河战力党规则实现

## 数据和接口

人物、骰面、天气与战术卡来自 `src/data` 固定提交的正式版数据。引擎把这些表适配为纯 JSON 状态；不执行下载数据中的脚本、表达式或路径。

- `createMatch(config, seed)` 建立对局。经典模式传两名玩家；共斗可传两名队友和 `bossPhases`，引擎自动补 AI 首领，也支持显式三名角色。`coopStageId` 采用该关原始战术卡权重和第一关的战术锁定。
- `startingSide` 可设为 `0`、`1` 或 `'random'`，默认 `0`。随机先手在首轮骰池、重投次数和行动权限初始化前，由同一随机流决定。联机 1v1 每局使用浏览器随机种子重新抽取先手，玩家席位与身份保持不变。
- `applyCommand(state, command)` 返回 `{ state, events, error? }`。错误时返回原来的 state 引用，不消费随机数、不部分修改对局。所有指令都带 `playerId`。
- `confirm` 可携带最终 `diceIds`，同一操作内校验骰子存在性、唯一性、数量、命定约束并确认，不产生中间 `select` 事件。交换阶段不能通过确认重新挑选集合；AI 也直接使用原子确认。
- `getLegalActions` 提供合法操作和选骰范围；`getPlayerPreview` 提供选骰攻防预览；`chooseAiCommand` 返回一条合法的策略指令。
- `projectState` 返回副本。网络接入层还必须检查发送连接是否控制该 `playerId`，AI 首领由房主推进。
- RNG 使用序列化的 xorshift32；重投、曜彩骰、随机天气、同点随机转换和商店抽样都走同一随机流。暂选及预览不消费随机数。状态及指令可重放。

## 已实现的规则范围

37 张收集卡、25 种可兑换曜彩骰及其原始版本、31 种天气、24 张战术卡、试用卡和 22 个共斗首领阶段。首领卡与同名普通人物分开处理。

经典回合：进攻方投骰并选择 → 防御方选择 → 结算 → 交换攻防。攻击默认 2 次重投、防御默认 0 次；技能和天气再修改。曜彩骰默认每局 2 次，选中后触发骰面技能，每个行动仅可使用一次。镀闪不直接提高人物数值，雷雨会按镀闪次数提高攻防；升级版曜彩骰需要明确装备。

选择集合同时用于两种操作：重投时重新投掷选中的骰子，未选骰子不变，随后清空选择；确认使用时才按攻防等级校验数量。暂选数量可超过攻防等级以便整组重投。曜彩骰可参与重投，不再次消耗曜彩骰使用次数。原教程与实机核验见 `docs/dice-interaction-review.md`。

共斗：队友可同时选骰 → 双方未选骰进入共享交换池 → 交换和使用战术卡 → 双方确认 → 首领防御或伤害结算。交换操作原子地校验两个骰子仍在正确位置，重复或失效指令会被拒绝。队伍有 3 点共享生命，倒下后消耗 1 点并恢复 1 HP，耗尽即败。首领全部阶段清空后胜利。

共斗每两回合一次商店，手牌最多 3 张，刷新花 1 战术点且每次商店最多一次。战术点基础每回合 +2；正常攻击造成伤害达到 5/10/15，按最高档获得 1/2/3；完美防御 +3、反击 +2、复活 +3、施加减益 +1。没有把三个伤害档叠加计算。

随机天气按发布配置的第 2/4/6/8 回合分组抽取；剧情可以传入固定 ID 序列。卡牌永久状态、下一回合增益、当前天气增益和本回合战术增益分开保存。

## 同人扩展与平衡

原版表保留在 `src/data/cards.json`；`customCards.json` 增加希儿，`cardBalance.json` 覆盖刃、绯英说明。实际卡池共 37 张。希儿命中后的再现每个进攻回合仅一次，剩骰按最终共享池归属计算；未造成攻击伤害则永久升级所选普通骰，最高 D12。刃额外 +2 次重投；绯英单骰忽略 7 点防御，不能穿透力场。见 `docs/custom-characters.md`。

## 明确采用的结算约定

公开配置给出了技能文案、参数和脚本路径，但仓库不含这些运行时脚本。因此下列交互是这个网页实现的确定性约定，不能称为原作程序逐帧移植：

1. 被选中的曜彩骰技能，以进攻方在前的顺序处理。
2. 获取跃升、骇入等修正；先跃升后同时应用骇入。
3. 根据修正后的骰面计算人物组合技能及天气；应用对应瞬伤和状态。
4. 处理结算前荆棘、超载；锁定本回合攻防值。
5. 逐次处理攻击、连击、洞穿、反击、反伤与虹吸；共斗的两个攻击者分别与首领防御比较。
6. 处理攻击后技能、中毒及回合末状态，然后切换回合。海瑟音按最终偶数骰数附毒，全偶数时在自己的整段攻击（含连击）结束后额外引爆一次；无须破防且这一次不扣毒层。回合末中毒按当前层数扣血、随后仅减一层。猛毒使二者伤害乘二，不能叠为四倍。攻击过程中新增的星期日荆棘保留到下一次结算前。

百分比数值统一向下取整；同类连击取最大额外次数，翻倍相乘。共斗的反击/减益奖励按每人每回合一次结算。击破首领阶段会立即进入下一阶段，击杀者对旧阶段的剩余连击停止，下一队友可继续攻击新阶段；保留旧阶段卡片的结算快照。爻光达到18攻时先清除自己的荆棘；防御超载按层数50%扣血；不屈作用于整个生效期间。默认200回合防卡死上限到达时判和棋，此上限是网页规则，未伪装为原作获胜规则。

`lastResolution` 从首个骰面瞬伤之前捕获初始卡片、生命、最终骰面、攻防和天气，并包含本次完整事件列表与ID范围。伤害事件的 `amount` 是实际扣血（包含0伤格挡）；`damageKind`、`sourceLabel`、`hpBefore/hpAfter`、毒/荆棘层数前后值、连击来源及实际击次说明每笔结算。复起/首领换阶段是随后独立的生命恢复事件。表现层按事件ID播放，不能把整轮生命差额再次当成一笔攻击。

预览可以展示已知数值、技能和战术支援，但最终还可能受对手骇入、随机跃升、瞬伤及阶段切换影响。AI 使用公开骰面选择，不读取将来的 RNG。

## 验证

`tests/game.rules.test.ts` 校验确定性、输入不可变性、非法和重复指令、攻防顺序、穿透力场、双对子连击、中毒、反击、命定约束、绯英自由选骰、星期日荆棘保留、战术手牌与刷新限制、共享复活、原子换骰和双方确认同步。此外逐一模拟全部 37 张收集卡，以及所有 22 个共斗首领阶段的两阶段完整 AI 对局，检查合法指令、数值有效性与结束性。

`tests/status-settlement.test.ts` 额外覆盖海瑟音0/4层毒与猛毒、格挡后引爆、连击仅引爆一次、普通/真毒液限制与重复猛毒、爻光真命运及天气连击、荆棘/超载/反击/反伤/不屈、同轮多次共斗复起、首领阶段身份和事件水位。设置 `SAVE_STATUS_EVIDENCE=1` 运行该测试，会输出 `artifacts/status-settlement-cases.json` 的实际固定种子事件记录。
