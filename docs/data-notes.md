# 数据覆盖、解释与已知边界

## 可验证范围

规范化数据包括 36 张玩家角色卡、28 张教程/NPC/Boss 专用卡、50 条骰子定义（其中 25 条为可装备的真曜彩骰）、24 张战术卡、31 条天气规则、28 条术语、132 条单人关卡配置、11 段经典战役、11 条共斗关卡配置及其 6 条单人游玩队友配置。NPC 专用内容与合法收藏分开导出。

角色生命、技能参数、攻防等级、普通骰组和卡牌星级来自原表。卡面与特效 prefab 的路径不是逻辑脚本。仓库未包含 `Config/Gameplays/LittleGame/DiceCombat/` 引用的原始执行脚本；网页规则引擎为根据描述、教程及公开玩法资料手写的实现，不能宣称直接运行原作代码。原游戏 3D 舞台、对白演出和时间曲线需要网页重建。

## 必须区分的概念

- 固有星级、镀闪档位、攻击等级、防御等级彼此独立。原文 Hash `16296959018007821396` 明确说明：镀闪不会对卡片效果产生影响。镀闪不得修改生命、技能、基础骰组或自动把普通曜彩骰换成真曜彩骰。
- `DiceIDPerRare` 前三个槽位构成普通骰池，第四个为特殊曜彩骰。`DiceCountPerRare` 第四项保留为 `prismaticStockCount`；不能将其和普通骰混投。初始使用次数以教程明确说明的通常每局两次为基准，输出 `prismaticUses=2`；没有该槽位的卡输出 0。特殊技能另外改变次数。第四项为旧角色 1、新角色 2，但其完整引擎含义无法仅凭表确认。
- 绯英缺失的攻击等级输出 0，表示交给特殊技能处理，不能默认为普通的三骰攻击。
- 特殊骰面的 ContentID 不等于点数，必须关联 ActivityDiceContentConfig.Content。骰面说明的第一个占位符是 Content，后续参数才是 SkillParam；已在导入时渲染。
- 星穹铁道文本 Hash 超过 JavaScript 安全整数范围。使用 Python 解析，禁止在浏览器直接 JSON.parse 上游大整数再关联文本。

## 剧情与进度

经典 11 段战役通过其 SubMissionID 关联原 MissionInfo 完成条件，明确对应 9001—9011 关卡，不按角色名猜测。天气 `ruleGroups` 附带每次变化的回合及候选天气 ID。新活动 V2PVEStage 的名称与卡牌为同关卡的单人游玩队友配置，已附到相同 ID 的共斗关卡上。

移除大世界行走和对话后的商城开放条件，通过原任务依赖图转换成对应战役完成记录。对话型节点继承前一场战斗的条件，初始教程对话视作进入小游戏时完成。这是浏览器版本对进度结构的改编。

资历使用 OfferingType 12，最高 25 级，1—10 级每级 50 经验，11—25 级每级 100 经验。原始关卡奖励、等级奖励和商店价格均保留，原游戏的星琼、信用点等主游戏奖励不计入本地小游戏。初始角色使用原始礼物奖励 2001691（火花花），初始货币为零。自由模式独立开放全部角色，不给剧情账户发放付费或原游戏奖励。首次通关与等级奖励不会因重复调用再次发放。

斯科特、砂金、姬子不是商城商品。为使无大世界的网页版本仍可完整收集，新增三场便携赠卡挑战：经典第二战之后挑战斯科特、经典最终战之后挑战砂金、共斗第六战之后挑战姬子。对手为对应角色，获胜后发放原奖励 2001695、15000503、12054200。砂金和姬子的任务名「银河战力党传说」「孤狼之血」保留原文；挑战入口和解锁里程碑是网页改编，不冒充原作剧情任务的完整复现。

原始普通牌手关卡 2001—4013 中实际存在的 116 场作为「街头切磋」收录，保留原始对手卡、镀闪档位、难度及奖励，每场首次完成可得 1 战力币和对应粉尘。网页统一在经典第一战后开放，用角色卡名标识牌局，不编造大世界 NPC 名称。两部主线全部首胜共提供 2700 资历，足够达到 25 级的 2000 资历门槛；街头牌局补足基本商城货币和全收藏镀闪所需粉尘。没有把重复胜利假设成可无限领取奖励。

## 上游数据限制

常量表部分 MapValue 以重复的 `IntValue` 键序列化，实际映射键已丢失。导入器以 `$entries` 保存全部有序值，避免普通 JSON 解析静默覆盖。镀闪成本的有序值为 60、60、60 / 180，最大档位为 2、2、3；网页按星级顺序重建为普通与二星最高镀金、三星可全息，升级费用 60 / 180，并在数据中标记 `ordered-values-inference`。这部分键值对应仍需与原始客户端逐项验证。

4.2 扩展中共斗进攻伤害获战术点有 5/10/15 阈值，原表不直接声明多档是否累加；精确时序应以录像回归案例校准。普通条件名、数值、金币奖励、收藏合法性均保留源数据，便于后续修正。

导入和资产验证：`python scripts/verify_data.py`。本地进度单测：`npx vitest run tests/progression.test.ts`。
