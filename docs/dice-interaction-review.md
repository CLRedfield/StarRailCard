# 选骰与重投交互核验

核验日期：2026-09-28。范围为经典对局的选骰、重投、曜彩骰和确认过程，以及共斗确认后的交换阶段。文档记录原始数据和本次实际观看的画面，区分直接证据与尚未完整实看的边界。

## 核心结论

**点击「重投」处理当前选中的骰子；其他骰子保持原点数。** 选中不是锁定保留。同一组高亮骰子可以用于重投，也可以在满足攻防数量要求时确认使用。先前网页规则说明将这层交互写反，现已纠正。

原教程依次引导点击两个骰子、点击重投、等待投掷结束、重新选择用于攻击的骰子、最后点击确认。原作实机也显示重投之后选择被清空；确认后，用于战斗的骰子才缩小并移动到角色上方的结算位置。

## 网页结算表现与精确数值

网页的权威规则一次完成结算，展示层使用独立时钟播放这一过程。`src/game/engine.ts` 在双方技能、骰面、天气与共斗同步/全力支援修正完成后，从实际用于攻击的 `values` 表记录 `GameState.lastResolution`，随后才进入伤害和下一回合。记录内容包括当前回合、进攻方、双方最终攻防值、最终选定骰子、效果以及实际攻击/反击/反伤记录。

`getPlayerPreview` 仍用于玩家选择期间的预览；它不是完整结算器，不能假定它已计算所有特殊骰面或对手改骰。因此正式比较画面直接使用 `lastResolution` 的最终值，不从受伤量反推，也不把下一回合已清空的骰池当作本次结算骰池。例子：测试中的贷款骰让选择预览为 13，但结算加入超载后实际攻击为 16；比较画面必须显示 16。

跃升和骇入沿用规则引擎已执行的随机目标，效果事件额外保存 `effectKind`、`targetId` 和 `diceChanges` 中的骰子 ID、原点数、最终点数。表现层逐个读取这些记录，并不重新抽取目标。确定性测试覆盖了银狼将自身 1 改为 6、再把对手 6 改为 2，最终以 16 攻击对 10 防御造成 6 点伤害的完整路径。

`src/lib/useBattlePresentation.ts` 的网页播放时长如下。这些数值是本项目的表现节奏，不是声称从原作逐帧测出的时长。

| 阶段 | 网页时长 | 展示行为 |
| --- | ---: | --- |
| 准备结算 `settle` | 200ms | 保留本轮角色、已选骰和生命值。 |
| 技能改骰 `transform` | 每个效果 720ms | 依次显示跃升或骇入；具体目标与点数变化来自规则事件。 |
| 最终比较 `compare` | 850ms | 同时展示双方真正参与结算的最终数值；生命值保持结算前状态。 |
| 攻击 `strike` | 650ms | 依据结算中的攻击方向播放角色出手和防御反馈，仍不提前扣血。 |
| 命中 `impact` | 850ms | 更新本轮牌桌上的生命值并发布伤害事件，播放受击爆花、浮字和声音。 |
| 减少动态效果 | 450ms | 保留静态最终数值比较，随后直接展示最新权威局面。 |

普通结算约 2.55 秒，每个改骰效果另加 0.72 秒。期间只锁定当前客户端操作和本地 AI 的下一条动作；规则状态与存档已经完成结算。更快到达的联机快照保存在最新状态引用中，演出结束跟进最新局面，不覆盖或回退权威状态。首次恢复存档、重新进入牌桌以及切换新局时不补播旧事件；卸载和退出会清理表现定时器。

改骰专属动画通过 `activeEffect` 播放，整批结算日志在受击阶段才交给伤害浮字层，防止提前推进事件 ID 水位后漏掉更早发生的瞬伤。生命值、下一回合骰子和胜利画面的切换也由同一表现时钟协调。人物技能引发的完整边界与手工重建的规则时序仍以 `src/game/RULES.md` 为准；本次画面核验没有证明所有角色技能、反击、连击或共斗组合都具有与这一常规攻击完全相同的原作镜头。

## 次数与角色、天气例外

通常进攻拥有两次重投，防御没有。一次重投操作作用于当前选中集合，不能按骰子颗数分别扣除次数。原始角色与天气数据还明确包含这些例外：

| 内容 | 原始 ID | 对重投的影响 |
| --- | --- | --- |
| 开拓妖精、自动机兵·甲虫、财富蕉师 | 264004、264005、264009 | 防御可重投一次。 |
| 爻光 | 264022 | 攻击可重投四次；本回合超过两次后的每次重投增加两层荆棘。 |
| 刃 | 264031 | 攻防均有六次重投，每次消耗两点生命。 |

| 鱼雨 | 天气 5 | 攻防额外增加一次重投。 |
| 细雪 | 天气 25 | 攻击回合未重投时，给予仅下回合可用的三层韧性。 |

## 证据边界与实现验收

以下已经有原文、原教程图片或实际观看画面直接支持：选中者重投、零选择不能重投、可少于确认数量重投、曜彩骰可以重投、一次多骰重投只扣一次机会、重投完成后清除高亮，以及确认后将战斗骰移至角色附近。

以下细节须区别于以上直接观察：

- 「一次可重投任意数量，包括超过攻防等级数量」得到 [Icy Veins 实机攻略](https://www.icy-veins.com/honkai-star-rail/cosmicon-roll-on)的明确说明，也符合原教程两个按钮的分工；本次尚未捕获选中超过攻防等级甚至全部骰子的完整官方操作片段。
- 已投出曜彩骰的重投按普通重投机会处理，与额外投出曜彩骰的使用次数分开，是结合两项教程规则得出的实现解释；本次尚未记录其两个计数器连续变化的完整录像。
- 录像的离散时间点不能给出原动画逐帧轨迹、精确持续时间或全部中间高亮状态；网页动效按这些已观察到的阶段重建。
- 重投允许再次得到同一点数。不得为了让动效看似改变而强制排除旧点数；本次没有发现本活动存在这种保证。

对应验收应比较目标骰子的 ID 与随机数推进，确认未选骰子的点数保持不变，并覆盖普通骰与曜彩骰混合重投、空集合、次数耗尽、特殊防御重投、确认数量不足/超出及共斗进入交换阶段等情况。涉及随机结果的测试不能只断言重投后数字必定不同。

2026-09-28 本轮验证：`npm test` 为 89 项通过，3 项公网测试默认跳过；开启 `SRC_MQTT_LIVE=1` 后，3 项真实 EMQX 测试另行全部通过，总用时 158.12 秒。固定种子 4321 的经典对局完成 9 回合、60 次指令，最终结算为 17 攻击对 8 防御；协作完成两个首领阶段、5 回合、75 次指令，最终双方攻击为 15 与 30，首领防御为 10。两种模式均在首个结算后断开客人连接，再从检查点恢复原席位与指令序号并继续到终局；最终完整状态和 `lastResolution` 在双方一致。测试结束后清理本次临时私房。
